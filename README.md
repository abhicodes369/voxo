# VOXO

A social app front end — feed, stories, reels, chat, search and settings — built as a
polished, motion-first mobile web experience.

**Live:** _(added after the first Cloudflare deploy)_

## What's in it

18 screens, all wired together with real navigation and persisted local state:

| Flow | Screens |
| --- | --- |
| Entry | Splash, 3-step Onboarding, Login, Create Account |
| Core | Home feed, Search / Explore, Create Post, Reels, Profile |
| Social | Story viewer, Chats, Chat thread, Notifications |
| Account | Menu, Settings, Account |

## Design notes

**Everything is vector.** There isn't a single image file in the repo. Each "photo" is a
seeded SVG scene generated by [`src/lib/art.tsx`](src/lib/art.tsx) — a hashed seed picks a
dusk palette, sun position, three dune ridges and a robed silhouette, so the same post always
renders the same artwork while the feed as a whole looks shot by one photographer. Full-bleed
surfaces (reels, stories) pass `tall` to get a portrait canvas instead of a sliced square.

**One motion vocabulary.** [`src/lib/motion.ts`](src/lib/motion.ts) defines the springs; every
screen enters through the same `Screen` wrapper, so route transitions are consistent app-wide.
Shared-element animation carries the tab pill, the category chips and the profile tab underline
via Framer Motion `layoutId`. Reduced-motion preferences are respected in CSS.

**Themeable by token.** Colours are CSS custom properties redefined under
`:root[data-theme="dark"]`. Dark mode is a single attribute flip, persisted to `localStorage`
along with likes, saves and follows.

## Stack

React 19 · TypeScript · Vite · Tailwind CSS v4 · Framer Motion · React Router

## Running locally

```bash
npm install
npm run dev
```

| Script | Does |
| --- | --- |
| `npm run dev` | Dev server with HMR |
| `npm run build` | Type check, then production build to `dist/` |
| `npm run preview` | Serve the built bundle |
| `npm run lint` | oxlint |
| `npm run deploy` | Build and publish to Cloudflare |

## Deploying

Hosted on Cloudflare Workers static assets. [`wrangler.jsonc`](wrangler.jsonc) sets
`not_found_handling: "single-page-application"` so client-side routes resolve on a hard refresh.

```bash
npx wrangler login   # once
npm run deploy
```

Pushes to `main` also deploy through [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml),
which needs two repository secrets: `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.

## Scope

This is a front end. Content in [`src/lib/data.ts`](src/lib/data.ts) is fixture data and auth
is a demo — any credentials sign you in. Likes, saves, follows, theme and sent messages are real
interactions, held in memory and `localStorage` rather than on a server.
